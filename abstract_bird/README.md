# Абстрактная птица

Локальный MVP на Python. Программа читает один или несколько комментариев‑воспоминаний: о том, чего человек хочет, что хочет обрести или чего добиться, а также о том, с чем он хочет расстаться или что хочет отпустить. По ним процедурно рисуется статичное изображение абстрактной птицы.

Программа:

1. загружает и нормализует текст;
2. определяет направление намерения (`acquire` / `release` / `mixed` / `unclear`);
3. эвристически анализирует эмоции без ML‑моделей;
4. извлекает ключевые слова, темы и визуальные мотивы;
5. переводит анализ в художественную спецификацию `BirdSpec`;
6. процедурно рисует птицу (Pillow + NumPy);
7. сохраняет PNG и JSON с параметрами анализа и генерации;
8. выводит в консоль краткий технический отчёт.

Работа идёт полностью локально: без интернета, внешних API, облачных сервисов и скачивания моделей или шрифтов.

> **Важно.** Результат — художественная интерпретация текста, а не психологическая диагностика. Словари и веса образуют систему художественной интерпретации и не являются психологически валидированной моделью.

## Художественная концепция

Птица — образ желания, которое стремится ввысь, или образ того, что человек отпускает. Связь текста и изображения заметна, но не буквальна: каждое свойство текста влияет сразу на несколько визуальных параметров.

- **Желание обрести** (`acquire`) даёт собранный силуэт, плотное тёплое ядро и линии, направленные к центру.
- **Желание отпустить** (`release`) даёт отделяющиеся частицы, свободное пространство, облегчённые внешние перья и светлую периферию. Отпускание не делает птицу мрачной: при высокой надежде оно выглядит как освобождение.
- **Смешанное намерение** (`mixed`) соединяет устойчивое ядро, раскрытые крылья и отделяющиеся частицы.

Буквальных иконок (сердце, домик, монета, самолёт, медицинский крест) нет, все мотивы абстрактны.

## Требования

- Python 3.11+ (проверено на Python 3.13.15, macOS);
- Pillow ≥ 10, NumPy ≥ 1.24, pytest ≥ 7.4 (проверено на Pillow 12.3.0, NumPy 2.5.3, pytest 9.1.1).

## Запуск

Коротко: после каждого запуска

1. открывается окно, в котором видно, как рисуется птица (фон → свечение → хвост и дальнее крыло → корпус → голова, клюв, ближнее крыло → частицы → ключевые слова); закройте окно, чтобы завершить программу;
2. птица сохраняется **новым файлом** `output/images/bird_<дата-время>_<seed>.png` (+ JSON с тем же именем в `output/analysis/`) — прежние птицы не перезаписываются и не удаляются;
3. до трёх ключевых слов запроса вписаны внутрь птицы и повторяют её линии: первое — по средней линии крыла, второе — по изгибу брюшка, третье — вдоль центрального пера хвоста; буквы поворачиваются по касательной к линии, размер подбирается под длину и толщину области, а цвет выводится из цвета этой части птицы (эффект гравировки). Шрифт каллиграфический: по умолчанию Trattatello (широкое перо), если его нет — Savoye LET, Snell Roundhand, Brush Script (macOS), Segoe Script/Gabriola (Windows), курсивы с засечками; свой шрифт — `--keyword-font путь.ttf` (для .ttc — `путь.ttc#индекс`, например `--keyword-font "/System/Library/Fonts/Supplemental/SnellRoundhand.ttc#1"`). Шрифты только локальные, ничего не скачивается;
4. текст запроса дописывается в историю `data/history/requests.csv`.

Текст из командной строки:

```bash
python bird_generator.py --text "Я очень хочу увидеть море и почувствовать свободу"
python bird_generator.py --text "Я хочу отпустить тревогу и перестать бояться перемен"
```

TXT (каждая непустая строка — отдельный комментарий):

```bash
python bird_generator.py --input data/examples/example_comments.txt
```

CSV (по умолчанию используется колонка `comment`, остальные колонки игнорируются):

```bash
python bird_generator.py --input data/examples/example_comments.csv
python bird_generator.py --input comments.csv --column text
```

Поддерживаются UTF‑8 и UTF‑8‑SIG, запятые и кавычки внутри полей, переносы строк внутри полей в кавычках. Если указанной колонки нет, используются `comment` или `text`, если они есть; иначе выводится ошибка со списком доступных колонок.

JSON (массив строк, массив объектов, объект `{"comments": [...]}` со строками или объектами):

```bash
python bird_generator.py --input data/examples/example_comments.json --text-field text
```

Если поля `--text-field` в объекте нет, программа проверяет поля `comment` и `text`.

Запуск без источника:

```bash
python bird_generator.py
```

В этом случае используется `data/input/comments.csv`. Если файла нет, программа выводит сообщение `Не указан источник текста. Передайте --text, --input или поместите CSV-файл в data/input/comments.csv.` и завершается с кодом 3.

Полный пример:

```bash
python bird_generator.py \
 --input data/examples/example_comments.csv \
 --column comment \
 --output output/images/bird.png \
 --analysis-output output/analysis/bird_analysis.json \
 --width 1600 \
 --height 1200 \
 --seed 42 \
 --supersampling 2
```

Демонстрация:

```bash
python bird_generator.py \
 --input data/examples/example_comments.csv \
 --column comment \
 --output output/images/example_bird.png \
 --analysis-output output/analysis/example_bird.json
```

## Художественная система: архетипы, композиции, материалы

Главный принцип: **смысл текста определяет характер птицы, художественные архетипы — её визуальный язык, а seed создаёт вариацию внутри безопасных границ.** Непредсказуемость возникает не из хаотичной случайности, а из неожиданного сочетания архетипа, материала, композиции и эмоционального профиля, поэтому все птицы выглядят частями одного арт-проекта. Это режим по умолчанию (`--style none`).

### Три слоя генерации

1. **Семантика текста** (`TextAnalysis`): эмоции, энергия, уверенность, намерение, темы, ключевые образы.
2. **Художественная режиссура** (`direct_art`): архетипы и их доли, композиция, материал, силуэт, палитровая стратегия, визуальный фокус, эффекты.
3. **Вариативность** — иерархическая случайность из производных seed: макроуровень (архетип, композиция, материал, силуэт), средний (форма крыла, хвост, палитра, текстура, эффекты), микроуровень (углы перьев, частицы, отклонения контура — в рендере). Все генераторы — локальные `random.Random`, выбор всегда взвешенный.

### Архетипы (`config/visual_archetypes.json`)

`light` (световая), `crystal` (кристаллическая), `typographic` (типографическая), `flow` (поток), `particles` (из частиц), `organic` (органическая), `digital` (цифровая), `memory` (птица-память). Вес каждого = `base + Σ affinity × сигнал` (например, надежда повышает light/flow/organic, тревога — crystal/particles/digital, нежность — organic/light/memory, желание отпустить — particles/flow/memory, уверенность — crystal/digital, грусть — memory/flow, темы моря и путешествия — flow). Затем добавляется seed-отклонение и выполняется взвешенный выбор **основного (55–75%), вторичного (20–35%) и необязательного акцентного (0–15%)** архетипа, максимум три, сумма 1.0.

### Композиции (`config/compositions.json`)

`iconic_front` (фронтальная икона, симметричные крылья, два глаза), `ascending_diagonal`, `quiet_profile`, `open_spiral`, `fragmented_escape`, `floating_horizontal`, `compressed_core`, `dual_direction`. Композиция меняет всю геометрию: наклон, подъём и раскрытие крыльев, положение головы, направление и длину хвоста, зону частиц (кольцо, спираль, след, побег…), положение света, центр масс и свободное пространство.

### Материалы (`config/materials.json`)

`light`, `glass`, `ink`, `particles`, `ribbons`, `letters`, `leaves`, `digital_grid`, `crystal`, `smoke`. Материал определяет, **как** рисуется каждая часть (прозрачные слои и свечение, стеклянные блики, чернила со штриховкой, россыпь точек, ленты, буквы, прожилки листьев, сетка с узлами, грани кристалла, размытый дым) — независимо от формы и композиции. На птицу — один основной и не более одного дополнительного материала (на периферии: хвост и внешние перья), один основной и один акцентный эффект. Несовместимые пары материалов перечислены в конфигурации.

### Силуэт, крыло, хвост, фокус, абстрактность

- силуэт: округлый, вытянутый, треугольный, каплевидный, широкий, хрупкий, симметричный, асимметричный;
- крыло: `pointed`, `rounded`, `broad`, `sickle`, `wave` (волновой ритм — так тема моря проявляется формально, без рисования моря);
- хвост: веер, ленты, вилка, короткий, спираль, раздвоенный;
- **один визуальный фокус**: глаз, световое ядро, кончик крыла, хвост, зона распада или акцент на груди (`focal_point`, `focal_strength`);
- `abstraction_level` ограничен 0.25–0.70, чтобы птица оставалась читаемой;
- отрицательное пространство: `negative_space`, `inner_void` (настоящая пустота внутри корпуса), `silhouette_openness`.

### Палитры (`config/palettes.json`)

Стратегии `analogous`, `complementary_accent`, `monochrome`, `dark_field_light_accent`, `warm_cool_contrast`. Базовый оттенок задаёт тема и эмоции, стратегия строит из него согласованные базовый, вторичный, акцентный цвета и цвет контура/свечения; RGB-каналы независимо не выбираются. Контраст птицы и фона проверяется.

### Редкие особенности

Примерно в 12% генераций (детерминированно по seed и с учётом эмоций): раздвоенный хвост, светящийся глаз, пустота внутри корпуса, вторичный затухающий силуэт, перья-буквы, кольцевой след, крылья из разных материалов, смещённое ядро, разлетающийся край, инвертированное свечение.

### Темы — формально, а не буквально

Море → волновой ритм крыла и поток; дом → тёплое защищённое ядро; любовь → парность и мягкая симметрия; деньги и карьера → золотистая кристаллическая геометрия; путешествие → траектория и вытянутый силуэт; память → слои и эхо-контуры; свобода → раскрытие и пространство; отпускание → размыкание силуэта и отделяющиеся частицы. Активных мотивов — не больше трёх.

### Генерация с отбором

Для каждого текста создаётся 5 кандидатов `BirdSpec` (производные seed через SHA-256, `--candidates 3–12`), каждый проверяется `validate_bird_spec` и при необходимости исправляется `repair_bird_spec` (детерминированно), затем оценивается без рендера:

```text
score = 0.25·читаемость силуэта + 0.20·цветовой контраст + 0.15·соответствие смыслу
      + 0.15·баланс композиции + 0.10·новизна + 0.10·согласованность мотивов + 0.05·баланс деталей
```

Рендерится только победитель. В JSON (`art_selection`) сохраняются число кандидатов, индекс и seed победителя, итоговая оценка, оценки по критериям, причины выбора и краткие оценки всех кандидатов. Веса — в `artistic_mapping.json → art_direction`.

Флаг `--avoid-recent-similarity` (по умолчанию выключен) снижает новизну кандидатов, похожих на последние птицы; сводки (архетип, композиция, материал, силуэт, палитра, сектор оттенка — без текстов) хранятся в `output/recent_specs.json`. Он нарушает строгую воспроизводимость, поэтому выключен по умолчанию.

### Слои рендера

1 фон → 2 дальние частицы (размыты) → 3 вторичный полупрозрачный силуэт / следы → 4 заднее крыло и хвост → 5 корпус и голова → 6 переднее крыло → 7 перья → 8 внутреннее ядро → 9 контурные акценты и глаз → 10 ближние частицы → 11 тонкая текстура (0.02–0.12) и цветокоррекция. Используются RGBA-слои, маски, размытие через уменьшенные копии, screen-наложение свечения, процедурный шум NumPy и supersampling. В окне предпросмотра видно, как слои появляются по порядку.

### Управление

```bash
python bird_generator.py --text "..."                                # художественная система, 5 кандидатов
python bird_generator.py --text "..." --candidates 8                 # больше кандидатов
python bird_generator.py --text "..." --archetype crystal            # задать основной архетип
python bird_generator.py --text "..." --composition iconic_front     # задать композицию
python bird_generator.py --text "..." --material letters             # задать материал
python bird_generator.py --text "..." --palette monochrome           # задать палитровую стратегию
python bird_library.py --archetype particles                         # коллаж птиц одного архетипа
```

`mapping_explanation.art` объясняет выбор архетипов (и какие сигналы их усилили), композицию, материалы, палитру, фокус и редкую особенность — без цитат из текста.

## Художественно-архитектурные стили

Поверх художественной системы можно включить один из 10 архитектурных стилей (они используют собственную палитру, орнамент и фактуру, поэтому по умолчанию выключены: `--style none`). `--style random` выбирает стиль случайно, `--style seed` — по seed; название стиля выводится в отчёт, записывается в JSON (`bird_spec.style`, `render.style_title`, `render.style_source`) и в имя файла (`bird_<дата>_<seed>_<стиль>.png`).

| Имя | Стиль | Что меняется |
|---|---|---|
| `art_nouveau` | Модерн (ар-нуво) | Растительные перья-листья, текучие линии «удар бича», приглушённые оливковые и золотые тона, арочная рамка |
| `art_deco` | Ар-деко | Золото на чёрном, копьевидные симметричные перья, лучи «солнечного взрыва», ступенчатая рамка |
| `bauhaus` | Баухаус | Чистые красный, жёлтый и синий, круги и треугольники, толстый чёрный контур, никакой декоративности |
| `gothic` | Готика (витраж) | Перья — стрельчатые арки, свинцовые переплёты, драгоценные цвета витража, стрельчатое окно за птицей |
| `constructivism` | Конструктивизм | Красный, чёрный и кремовый, острые треугольные перья, диагональная композиция, типографская зернистость |
| `ukiyo_e` | Японская гравюра (укиё-э) | Плоские приглушённые цвета, тонкий контур, перья-капли, красное солнце и стилизованные волны, фактура бумаги |
| `byzantine` | Византийская мозаика | Золотой фон, нимб вокруг головы, лазурь и пурпур, всё изображение выложено смальтой |
| `minimalism` | Минимализм | Мало деталей, приглушённые цвета, тонкая линия, много пустого пространства |
| `baroque` | Барокко | Пышное оперение, золотые завитки-волюты, глубокие насыщенные цвета, драматическая виньетка |
| `brutalism` | Брутализм | Бетонные серые тона, прямоугольные блочные перья, тяжёлые контуры, фактура необработанного бетона |

Задать стиль самостоятельно:

```bash
python bird_generator.py --text "..." --style bauhaus
python bird_generator.py --text "..." --style готика        # можно по-русски
python bird_generator.py --text "..." --style seed          # стиль по seed — воспроизводимо
python bird_generator.py --list-styles                      # список стилей
```

Одна птица сразу во всех 10 стилях и коллаж из них (seed общий, поэтому форма одинакова и различается только стиль; каждая птица сохраняется отдельным файлом, коллаж — в `output/collages/styles_<дата>_<seed>.png` и открывается автоматически):

```bash
python bird_generator.py --text "..." --all-styles
```

Стиль меняет «почерк» птицы: палитру (эмоциональный цвет частично сохраняется), форму перьев (листья, копья, арки, капли, блоки…), толщину и цвет контура, фон с орнаментом (арочная рамка, солнечные лучи, стрельчатое окно, красное солнце и волны, волюты…) и финальную фактуру (смальта, бумага, зерно, бетон, виньетка). Эмоциональную геометрию — размах и подъём крыльев, наклон, хвост, асимметрию, частицы отпускания — по-прежнему задаёт текст. При одинаковых тексте, seed и стиле изображение воспроизводится побайтно. Контрольная галерея рисуется художественной системой (без архитектурного стиля). В `bird_library.py` есть фильтр `--style`.

## Окно «Отпусти»

Оконный режим для людей, которые не пользуются терминалом. Слева — крупный заголовок **«Отпусти»**, призыв *«Напишите о том, чего вы очень хотите — или что хотите отпустить. Это может быть мечта, чувство, воспоминание или перемена. Ваши слова превратятся в уникальную птицу.»*, текстовое поле и кнопка **«Отпусти»**. Справа, в том же окне, птица рисуется слой за слоем, затем показывается готовый PNG с короткой подписью (эмоция, архетип, композиция, материал, слова) и ссылкой «Открыть файл».

Запуск (любой способ):

```bash
python bird_app.py
python bird_generator.py --gui
```

На macOS можно дважды щёлкнуть по файлу `Отпусти.command` в Finder (он использует окружение `.venv` проекта).

- Кнопку заменяет сочетание Cmd/Ctrl + Enter.
- Текст короче 10 символов не отправляется — появляется подсказка.
- Генерация идёт в фоновом потоке, окно не зависает; кнопка на это время неактивна.
- Каждая птица сохраняется отдельным файлом в `output/images/` (JSON — в `output/analysis/`), текст дописывается в историю `data/history/requests.csv`, как и при запуске из терминала.
- Нужен tkinter (входит в стандартную установку Python с python.org); шрифт заголовка — Trattatello, если он есть в системе, иначе другой установленный.

## Окно «птица рисуется»

Во время рендера программа записывает ~50 промежуточных кадров, а затем показывает их в окне (tkinter из стандартной библиотеки) с подписью текущего этапа и финальным PNG в конце. Сам рендер длится меньше секунды, поэтому показ замедлен до нескольких секунд — иначе процесс не увидеть. Кадры — это настоящие промежуточные состояния холста; на итоговое изображение запись кадров не влияет (это проверено тестом). Окно отключается флагом `--no-preview`. Если окно открыть нельзя (нет графического окружения или tkinter), программа открывает готовый PNG в системном просмотрщике.

## Библиотека птиц и коллаж

Все птицы копятся в `output/images/`, а их отчёты — в `output/analysis/`. Команда `bird_library.py` собирает из них одну картинку‑коллаж с подписями (дата и время, доминирующая эмоция, намерение, ключевые слова), сохраняет её новым файлом в `output/collages/` и открывает:

```bash
python bird_library.py                        # все сохранённые птицы
python bird_library.py --date 2026-09-29      # за конкретный день (локальная дата)
python bird_library.py --date сегодня         # за сегодня
python bird_library.py --emotion надежда      # доминирует надежда (можно hope, joy/радость, sadness/грусть,
                                              # anxiety/тревога, anger/гнев, tenderness/нежность, surprise/удивление)
python bird_library.py --intent release       # только птицы «отпустить» (acquire, release, mixed, unclear)
python bird_library.py --date сегодня --emotion тревога   # фильтры можно сочетать
python bird_library.py --style баухаус         # только птицы в стиле Баухаус
python bird_library.py --list                 # только список в консоли, без коллажа
```

Другие параметры: `--tile 360` (размер миниатюры), `--columns N`, `--output путь.png`, `--no-open`, `--analysis-dir папка`. Доминирующая эмоция — эмоция с наибольшим эффективным значением (значение × уверенность). В коллаж попадает и контрольная галерея, так как она лежит в `output/analysis/gallery/`.

## История запросов

Каждый запуск через `bird_generator.py` дописывает в `data/history/requests.csv` строку на каждый проанализированный комментарий: `comment`, `generated_at`, `image`, `analysis`, `intent_type`, `keywords`. Файл никогда не перезаписывается, только пополняется. Другой файл — `--history-file путь.csv`, отключить — `--no-history`.

Поскольку у истории есть колонка `comment`, её можно подать на вход и получить одну общую птицу из всех запросов:

```bash

```

## Выходные файлы

- **PNG** (RGB) без метаданных: в файл не записываются время, текст, ключевые слова и пути.
- **JSON** (UTF‑8, `ensure_ascii=False`) содержит поля `schema_version`, `generated_at`, `run_parameters`, `input_statistics`, `truncated`, `analysis` (`TextAnalysis`), `bird_spec` (`BirdSpec`), `mapping_explanation`, `render`, `paths`, `config_versions`, `config_hashes` и `warnings`. С флагом `--include-source-text` добавляется `source_comments`, с `--debug` — `diagnostics` (счётчики сигналов и вклады в параметры, без текста).

Оба файла записываются атомарно: сначала во временный файл в той же директории, затем идёт проверка (PNG открывается и проходит `verify()`, размер совпадает; JSON перечитывается), и только после этого выполняется `os.replace`. Прежний корректный результат не удаляется, пока новый не записан; при ошибке временный файл удаляется.

## Подготовка входа

Порядок обработки: чтение → удаление пустых записей → нормализация пробелов → удаление точных дублей → лимит `--max-comments` → лимит `--max-characters` → проверка минимальной длины (10 символов).

Нормализация сохраняет регистр, пунктуацию (`!`, `?`, многоточия) и эмодзи. Для словарного анализа отдельно создаётся версия в нижнем регистре с заменой `ё → е` и сжатием растянутых букв («оооочень» → «очень»). Если комментарий не помещается в лимит символов, он исключается целиком. Обрезается только первый комментарий, если он один превышает лимит (по границе слова). При срабатывании любого ограничения `truncated = true` и добавляется предупреждение.

В статистике сохраняются `source_comment_count` (непустые записи), `unique_comment_count`, `duplicate_comment_count`, `analyzed_comment_count` и `truncated`.

## Направление намерения

| `intent_type` | Смысл | Примеры маркеров |
|---|---|---|
| `acquire` | получить, создать, достичь, сохранить | хочу, мечтаю, стремлюсь, увидеть, почувствовать, начать, найти, обрести… |
| `release` | отпустить, прекратить, забыть, оставить в прошлом | отпустить, забыть, перестать, избавиться, освободиться, «оставить … в прошлом», «больше не хочу», «не бояться»… |
| `mixed` | заметны оба направления | «хочу перестать бояться и начать путешествовать» |
| `unclear` | направление не определено | нейтральный текст |

Маркеры задаются шаблонами в `phrase_rules_ru.json`: `слово*` означает префикс, `~` — пропуск до трёх слов внутри предложения. Длинные шаблоны сопоставляются раньше коротких. Слабое «хочу» не засчитывается как приобретение, если сразу за ним идёт глагол отпускания («хочу отпустить»).

Эмоция внутри конструкции отпускания («хочу перестать тревожиться», «освободиться от тревоги», «хочу не чувствовать тревогу») не пропадает: тема сохраняется, а значение эмоции ослабляется коэффициентом `release_scope_emotion_factor` (0.4). Кроме того, повышаются надежда и `release_strength`. В итоге тревога во фразе «Я хочу перестать тревожиться» ниже, чем во фразе «Я сильно тревожусь и боюсь», но больше нуля.

`intent_targets` содержит до пяти объектов намерения (приведённых к лемме, если слово есть в таблице лемм), а не полные предложения.

## Эмоциональные параметры

| Параметр | Смысл | Нейтральное значение |
|---|---|---|
| `valence` | негативная ↔ позитивная окраска | 0.5 |
| `arousal` | спокойствие ↔ возбуждение | 0.5 |
| `intensity` | сила желания или переживания | 0.5 |
| `dominance` | уязвимость ↔ ощущение контроля | 0.5 |
| `hope`, `joy`, `sadness`, `anxiety`, `anger`, `tenderness`, `surprise` | эмоции | 0 (у `hope` базовое значение 0.1) |

Все значения лежат в диапазоне 0–1. `dominance` (ощущение контроля в тексте) и `confidence` (техническая уверенность анализа) — разные величины.

Источники сигналов: словарь слов, устойчивые фразы (обрабатываются раньше слов, и их слова повторно не учитываются), усилители («очень», «безумно»…), ослабители («немного», «наверное», «может быть»…), отрицания («не», «ни», «никогда», «больше не»), конструкции отпускания, пунктуация (`!`, `?!`, `???`, `…`), слова заглавными буквами, повторы слов и букв, эмодзи (со слабым весом 0.5).

Отрицание не инвертирует значения механически. «Я не счастлив» снижает радость и сдвигает окраску в негативную сторону. «Я больше не боюсь» почти убирает тревогу, повышает `dominance`, немного повышает `valence` и надежду. Восклицания повышают `arousal` и `intensity`, но не гнев. Многоточие немного повышает неопределённость.

Для биполярных параметров сумма вкладов переводится в значение через `0.5 + 0.5·tanh(k·x)`, для эмоций — через насыщение `1 − e^(−k·x)`.

## Агрегация нескольких комментариев

Несколько комментариев дают **одну коллективную птицу**. Каждый комментарий анализируется отдельно, затем результаты объединяются. Коэффициенты хранятся в `artistic_mapping.json → aggregation`:

- вес комментария равен `0.6 + 0.15·число_сигналов + 0.1·ln(1+число_слов)` и ограничен диапазоном 0.5–2.0, поэтому длинный комментарий не подавляет короткие;
- `valence`, `arousal`, `intensity`, `dominance` вычисляются как средневзвешенное;
- эмоция вычисляется как `0.7 · средневзвешенное + 0.3 · максимум`, чтобы сильная эмоция короткого комментария не терялась;
- намерение определяется по долям приобретения и отпускания: если меньшая доля не ниже 0.2, итог `mixed`; если направленных сигналов меньше 30% общего веса, итог `unclear`.

## Уверенность анализа

`score_confidence` вычисляется для каждого параметра по формуле `0.15 + 0.8·(1 − e^(−0.9·свидетельства))`. Результат умножается на долю распознанных слов, на штраф за противоречивые сигналы и на коэффициент языка (ru — 1.0, mixed — 0.7, en — 0.5, unknown — 0.35); кроме того, есть небольшой бонус за число комментариев. Значение, полученное только из базового, получает низкую уверенность.

Перед маппингом применяются эффективные значения:

```text
биполярные:  effective = 0.5 + confidence · (value − 0.5)
эмоции:      effective = confidence · value
намерение:   сила влияния умножается на intent_confidence
```

Поэтому низкая уверенность даёт более нейтральную птицу, а не ошибку.

## Художественный маппинг

`BirdSpec` — единственный вход рендерера; функции рисования никогда не получают `TextAnalysis` напрямую. Каждый параметр в `artistic_mapping.json → parameters` задаётся линейной формулой:

```text
parameter = clamp(bias + Σ коэффициент · сигнал + seed-вариация)
```

Сигналы: эффективные `valence/arousal/intensity/dominance` минус 0.5, эффективные эмоции, `acquire`, `release`, `mixed`, `detail` (ограниченный вклад объёма текста — длина не влияет на размер птицы) и флаги `theme_<id>` / `motif_<id>`.

Основные связи:

- высокий `valence` даёт светлую палитру, светлый фон, округлость и мягкий контраст; низкий — тёмный фон, угловатость и фрагментацию;
- высокий `arousal` даёт наклон и диагональ, острые крылья и больше мелких перьев; низкий — горизонтальность, широкие округлые крылья и меньше шума;
- `intensity` влияет на размер, насыщенность, толщину линий и свечение;
- высокий `dominance` даёт устойчивый корпус, раскрытые крылья, поднятую голову и симметрию; низкий — прозрачность и асимметрию;
- `hope` поднимает крылья и даёт светлые акцент и свечение; `joy` даёт тёплые чистые акценты и раскрытый хвост; `sadness` опускает хвост и голову, вытягивает корпус и примешивает холодный синий; `anxiety` даёт асимметрию, дробные перья и колебания контура; `anger` даёт острый длинный клюв, угловатые перья, красный акцент и мотив `fire`; `tenderness` даёт пастель, мягкие формы и внутреннее свечение; `surprise` увеличивает глаз и добавляет необычный акцент.

Цвет задаётся в HSL: базовый оттенок определяет главная тема, эмоции сдвигают его не более чем на 12%, грусть примешивает холодный синий. Второй цвет аналогичный или комплементарный (при высоком возбуждении или гневе), акцент зависит от доминирующей эмоции. Фон контрастирует с птицей: светлота различается минимум на 0.3.

`mapping_explanation` в JSON строится по шаблонам и срабатывает только тогда, когда правило действительно применилось (эмоция выше порога, соответствующий параметр изменился). Исходный текст и цитаты в объяснение не попадают.

### Визуальные мотивы

Все 24 мотива из ТЗ реализованы абстрактно. Фоновые мотивы: `waves`, `horizon`, `stars`, `dark_field`, `clouds`, `path`, `vertical_shapes`, `technology`, `music`, `organic_lines`. Мотивы, встроенные в птицу: `open_wings` (лучи за крыльями), `separated_particles`, `open_space` (разреженный фон, светлая периферия), `faded_layers` (полупрозрачные копии крыла), `echo_lines` (эхо‑контуры корпуса), `warm_core`, `warm_glow`, `paired_shapes`, `love` (парные дуги), `fire` (язычки на хвосте), `leaves`, `color_fragments`, `sharp_geometry`, `home` (абстрактное гнездо‑дуга). Мотивы выбираются по кругу из групп «намерение → темы → эмоции», максимум 8.

Теме «творчество» в ТЗ сопоставлены `color_fragments` и `asymmetry`. `asymmetry` нет в списке мотивов, поэтому она реализована как член маппинга `theme_creativity → wing_asymmetry`.

## Seed и воспроизводимость

- Если seed задан через `--seed`, используется он.
- Иначе seed вычисляется как первые 8 байт SHA‑256 от нормализованных уникальных анализируемых комментариев (в исходном порядке), соединённых стабильным разделителем. Встроенный `hash()` не используется.
- Вся случайность идёт через локальный `random.Random(seed)`; глобальное состояние `random` не используется. Вариация ограничена `random_variation.maximum = 0.07` на параметр и ±10° оттенка, то есть около 80–90% значения определяет анализ.
- Время, UUID и порядок `set` на рендер не влияют. `generated_at` есть только в JSON.
- Хеши конфигураций в seed не входят. Поэтому **изменение конфигурации может изменить `BirdSpec` и PNG при прежних тексте и seed**; чтобы найти причину, сравните `config_versions` и `config_hashes` в JSON.
- Побайтовая воспроизводимость PNG гарантируется в одном окружении с одинаковыми версиями Pillow и NumPy. Ключевые слова рисуются системным шрифтом, поэтому их вид зависит от установленных шрифтов; с `--hide-keywords` шрифт на изображение не влияет.

## Конфигурационные файлы

У каждого файла есть поле `"schema_version": "1.0"`. При запуске проверяются существование файла, корректность JSON, версия схемы, наличие обязательных разделов и типы значений. Об ошибке сообщается понятным текстом с именем файла (код 4). В JSON результата сохраняются версии конфигураций и первые 12 символов SHA‑256 каждого файла. Обычный запуск конфигурации не перезаписывает.

- `emotion_lexicon_ru.json` → `words`: слово или префикс `основа*` → вклады в параметры (сдвиги −1…1 и эмоции 0…1).
- `phrase_rules_ru.json` → `phrases` (с полями `category`, `modifier`), `intensifiers`, `diminishers`, `negations`, `overcome_prefixes`, `intent_markers.acquire/release`, `emoji`.
- `themes_ru.json` → `themes` (20 тем: `name`, `words`, `motifs`, `hue_range`) и `lemmas` (небольшая таблица приведения форм к лемме для ключевых слов и целей).
- `artistic_mapping.json` → `limits` (`maximum_feather_count`, `maximum_particle_count`, `maximum_keyword_count`, `maximum_theme_count`, `maximum_motif_count` и др.), `random_variation`, `aggregation`, `analysis`, `safe_ranges`, `colors`, `emotion_motifs`, `intent_motifs`, `parameters`.

## Ограничения эвристического анализа

- Анализ основан на словарях и правилах, поэтому не понимает иронию, сложный синтаксис, контекст за пределами соседних слов и редкую лексику.
- Отрицание учитывается в окне до трёх слов до эмоционального слова внутри одного сегмента (до запятой).
- Полноценно поддерживается только русский язык. Английский и смешанный текст обрабатываются без падения, но почти не распознаются; в JSON и лог добавляется предупреждение.
- Словари демонстрационные и неполные, веса подобраны вручную для художественного результата.

### Ограничения морфологии

Морфологического анализатора нет. Формы слова сопоставляются через точные слова и префиксы (`трев*` покрывает «тревога», «тревожусь», «тревожно»). Префиксы иногда дают ложные совпадения, а формы, не покрытые словарём, не распознаются. В ключевых словах разные формы одного слова могут считаться разными, кроме форм из таблицы `lemmas`.

## Конфиденциальность

- По умолчанию исходные комментарии **не** сохраняются в JSON, **не** выводятся в консоль и не попадают в debug‑лог и объяснения маппинга. Дополнительные поля CSV и JSON (id, даты, источник) не сохраняются.
- Нормализованные комментарии попадают в JSON только с флагом `--include-source-text`.
- **Исключение по вашему выбору:** история запросов `data/history/requests.csv` хранит тексты запросов накопительно (включена по умолчанию, отключается `--no-history`). Папка исключена из Git; удаляйте файл, когда история больше не нужна.
- Ключевые слова запроса (отдельные слова, не предложения) рисуются на изображении по умолчанию; для обезличенных картинок используйте `--hide-keywords`.
- Текст никуда не отправляется, все вычисления локальные.
- Данные рекомендуется **обезличивать**. Имена и контакты для генерации не нужны.
- Реальные данные **нельзя помещать в публичный Git**: `data/input/*` и результаты в `output/` исключены через `.gitignore`.
- Удаляйте данные и результаты, когда их хранение больше не требуется.
- Демонстрационные данные в `data/examples/` и `tests/fixtures/` вымышлены.

## Тесты

```bash
python -m pytest
```

Тесты используют `tmp_path`, не обращаются к интернету и `data/input` и не зависят от абсолютных путей. Они покрывают чтение всех форматов, нормализацию, дубли, лимиты, коды ошибок, диапазоны значений, различение `acquire`, `release` и `mixed`, различение «боюсь» и «больше не боюсь», «тревожусь» и «хочу перестать тревожиться», стабильность seed, независимость от глобального `random` и `PYTHONHASHSEED`, одинаковый PNG при одинаковом входе, отсутствие текста в JSON и логах, отсутствие шрифта, повреждённую конфигурацию, ослабление влияния при низкой уверенности, отличие отпускания от прямой тревоги и различие контрольных текстов по значимым параметрам. PNG не сравниваются с заранее заданным хешем: две генерации сравниваются в одной среде.

## Производительность

При 1200×1200 и supersampling 2 генерация одной птицы на этой машине (macOS, x86_64) художественной системой занимает около 1.2–3 с (5 кандидатов оцениваются без рендера, рендерится только победитель); с архитектурным стилем — около 0.5 с. Фон‑градиент и свечение считаются в уменьшенном разрешении. Количество перьев, частиц, ключевых слов, тем и мотивов ограничено в `artistic_mapping.json → limits`.

> При 4096×4096 и `--supersampling 3` рисование идёт на холсте 12288×12288. По оценке, это требует 1,5–2 ГБ оперативной памяти и больше (не измерялось) и заметно больше времени.

## Ограничения MVP

- Только статичное изображение: нет анимации, звука, веб‑интерфейса и базы данных.
- Анализ эвристический (см. выше) и не является психологической оценкой.
- Художественное качество изображений проверено визуально только на контрольной галерее в одном окружении; автоматические тесты проверяют измеримые свойства (размер, режим, непустоту, различия параметров).
- Ключевые слова на изображении рисуются только при наличии локального системного шрифта с кириллицей (проверяется список типичных путей macOS, Linux и Windows). Если такого шрифта нет, слова не рисуются и добавляется предупреждение.
- Обрезка первого слишком длинного комментария идёт по символам Unicode и может разорвать составной эмодзи (последовательность с ZWJ).
- Тема «освобождение и отпускание» определяется по тем же глаголам, что и намерение, поэтому при отпускании она часто становится главной темой и задаёт оттенок.

## Направления развития

- Заменить эвристический анализатор на локальную NLP‑модель. Архитектура это допускает: достаточно формировать тот же `TextAnalysis`, а `BirdSpec` и рендерер менять не нужно.
- Добавить морфологический анализатор для лемматизации.
- Анимировать полёт и отделение частиц.
- Озвучить птицу, связав звук с эмоциональным профилем.
